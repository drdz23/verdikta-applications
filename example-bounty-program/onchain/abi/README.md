# BountyEscrow merged ABI

`BountyEscrow.json` is the ABI agents should load. It is a plain JSON array,
usable directly with ethers (`new Contract(address, abi)`), viem, web3.py, or
`cast --abi`.

## Why a merged file

BountyEscrow answers every selector it does not implement itself by
STATICCALLing into `BountyEscrowLens` (see "Read-only extension (lens)" in
`contracts/BountyEscrow.sol`). The lens views — `nextAction`,
`getEffectiveBountyStatus`, `isAcceptingSubmissions`, `canBeClosed`,
`prepareCutoff`, `getSubmissions`, `getSubmissionsPage`, `getBounties`,
`getOracleResult`, `MAX_BATCH` — are therefore callable **at the escrow
address**, but the escrow's own compiled/verified ABI does not list them. An
agent that pulls the ABI from a block explorer gets an interface that appears
to lack them. This file is the escrow ABI plus those lens entries.

## Provenance

- Generated by `scripts/build-merged-abi.js` from the Hardhat artifacts
  (`artifacts/contracts/BountyEscrow.sol/BountyEscrow.json` and
  `.../BountyEscrowLens.sol/BountyEscrowLens.json`), build-info
  `e94b4379bc8d87dc00f2d7936c1735f8`, solc 0.8.23+commit.f704f362, optimizer
  200 runs, viaIR, evmVersion paris.
- The escrow portion is byte-for-byte the ABI Sourcify serves for the verified
  Base mainnet deployment (exact match).
- Regenerate and commit on every contract change:
  `npx hardhat compile && node scripts/build-merged-abi.js`
  (`node scripts/build-merged-abi.js --check` fails when the file is stale).

## Where to get it without this repository or the website

- IPFS (content-addressed; the CID commits to these exact bytes):
  `QmZa2NtTne6xj8c3ZBH7tPrLi2ZJwjaoKN1RyH2S6pLx59`
  e.g. https://gateway.pinata.cloud/ipfs/QmZa2NtTne6xj8c3ZBH7tPrLi2ZJwjaoKN1RyH2S6pLx59
  (where it is pinned), `ipfs cat QmZa2NtTne6xj8c3ZBH7tPrLi2ZJwjaoKN1RyH2S6pLx59`
  on a local node, or any other gateway. Verify: sha256 of the bytes must equal
  sha256 of this repository's `BountyEscrow.json`.
- Sourcify (keyless API, verified source for every deployed contract):
  `https://sourcify.dev/server/v2/contract/<chainId>/<address>?fields=abi`
  Note that Sourcify serves each contract's OWN ABI, so fetch both the escrow
  and the lens and concatenate, or use this merged file.
- Website mirror (convenience only): `GET /api/abi/BountyEscrow.json` and
  `GET /api/abi` (addresses + verification links) on bounties.verdikta.org and
  bounties-testnet.verdikta.org.
