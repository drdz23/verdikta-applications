## What changed since the 2026-10-01 notes

- **There is no "stable" channel for a script install.**
  - Source installs track `main`, "the only valid source channel" ([D] getting-started/updating; `scripts/install.sh` `BRANCH="main"`).
  - Stable and canary exist only for Desktop, the Docker image tags and Termux.
  - A fresh install today runs main HEAD, not v0.21.5. Pinning `--commit` to the release is expected to fail, because the release has no `pm/` directory (inferred, not tested).
- **Main installs Python 3.14 and Node 26.7.0 itself**, through its own package manager (`pm/lock.json`). Node is required, not optional.
- **Tirith is still on by default** (pinned 0.4.2) and still needs glibc 2.34+ (issue #118256, open). Ubuntu 24.04 has 2.39. Under the Docker backend Tirith is never consulted (next bullet).
- **Docker backend: every command guard is skipped when the sandbox has no host bind mounts**, except the owner's `approvals.deny` globs. That includes approval prompts, Tirith and the "hardline" list ([M] `tools/approval.py` `_should_skip_container_guards`). The container is the boundary. Hermes' own Python process (memory and skill writes, MCP, plugins, the web tools) stays on the host.
- **The non-root `hermes` user with linger, and `skills.write_approval: true`, are still right.** With approval on, every `skill_manage` write is staged under `~/.hermes/pending/skills/` ([D] features/skills). The curator's archiving is not gated; `curator.enabled: false` stops it.

## Install and run

- **Install:** `curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash`. No root needed, except that `libatomic1` must be present.
  - Useful flags: `--non-interactive`, `--skip-browser`, `--skip-computer-use`.
  - Layout: code in `~/.hermes/hermes-agent`, launcher `~/.local/bin/hermes`, settings `~/.hermes/config.yaml`.
- **Credential stores, by path only (never read):** `~/.hermes/auth.json`, `~/.hermes/.env`, `~/.hermes/vault/`, `~/.hermes/mcp-tokens/`, and each profile's copies under `~/.hermes/profiles/<name>/`.
- **Sign-in is the owner's:**
  - `hermes model` (wizard), or `hermes auth add openai-codex`, which uses a device code, so no tunnel is needed.
  - Anthropic OAuth needs Claude Max plus extra-usage credits.
  - `auth.adopt_external_logins: false` stops Hermes borrowing other CLIs' logins.
- **Service:** `hermes gateway install` gives a systemd user unit; run `sudo loginctl enable-linger hermes` so it survives logout. The gateway is needed only for messaging, cron and the API server.
- **Ports:** nothing listens by default and nothing inbound is needed. The API server binds `127.0.0.1:8642` when enabled and requires `API_SERVER_KEY`.
- **Profiles:** `hermes profile create <name>` gives separate config, memory, skills and `state.db`. There is no per-session "forget".
- **Transcripts:** stored in `~/.hermes/state.db` (SQLite, table `messages`, with `tool_calls` as JSON). Export with `hermes sessions export out.jsonl --session-id <id>`.

## One-shot runs prompt differently (verified)

- `hermes -z` and `hermes chat -q --oneshot` set `HERMES_SINGLE_QUERY_SESSION=1` ([M] `hermes_cli/oneshot.py:280`, `cli_single_query.py:514`).
  - The skills block then says to load a skill "only when it carries domain knowledge you lack" ([M] `agent/oneshot_footprint.py`).
  - Interactive and gateway sessions say instead: "If a skill matches or is even partially relevant to your task, you MUST load it" ([M] `agent/prompt_builder.py:1445`).
- **So an evaluation run through `-z` would measure a weaker trigger than real chat use.** Gateway sessions, including the loopback API server (`POST /api/sessions/{id}/chat`), use the interactive text.
- The interactive text also says "If a skill has issues, fix it with skill_manage(action='patch')". Hence `skills.write_approval: true`.

## Skill format and loading

- **Frontmatter** ([M] `agent/skill_utils.py:66`):
  - It reads `name` (falls back to the directory name) and `description`.
  - Optional top-level keys: `version`, `author`, `license`, `platforms`, `required_environment_variables`, `compatibility`.
  - Optional `metadata.hermes.*`: `tags`, `related_skills`, and conditional activation (`requires_tools`, `fallback_for_tools`, and others).
  - Unknown keys such as `metadata.openclaw` are ignored, but `skill_view` returns the whole `metadata` object to the model.
- **The index truncates the description to 57 characters plus "..."** (*verified*, [M] `agent/skill_utils.py:822-834`, `SKILL_PROMPT_DESC_LIMIT = 60`).
  - Ours shows as "Use when the owner wants or allows outside, independent o...".
  - The full description, up to 1,024 characters, appears only in `skills_list` and on `skill_view`.
- **Opening a skill:**
  - `skill_view(name)` returns the whole SKILL.md plus `skill_dir`, an absolute host path.
  - `skill_view(name, file_path)` reads any file inside the skill directory; `..` is refused.
  - The `linked_files` hint lists only `references/*.md`, templates and `scripts/*.{py,sh,js,ts,…}`, not `.mjs`, `schemas/` or `examples/`. SKILL.md names its files, so this is harmless.
- **Scripts run through the `terminal` tool.** Under the Docker backend, skills are mounted read-only at `/root/.hermes/skills/<rel>`, but `skill_dir` and `${HERMES_SKILL_DIR}` carry the host path (*verified*, [M] `tools/credential_files.py:167`; no translation found). The smoke test must confirm how the agent finds `scripts/preview.bundle.mjs`.
- **Where skills live:** `~/.hermes/skills/[<category>/]<name>/`, plus `skills.external_dirs` and trusted project directories.
  - There is no install-from-local-directory command; copy the folder in.
  - The prompt index is frozen per session, so an install applies to new sessions.
  - `skills.disabled` and `skills.platform_disabled` switch skills off.

## Always-on instructions (the AGENTS.md equivalent)

- **Context files** (first match wins):
  1. `.hermes.md`/`HERMES.md`
  2. `AGENTS.md` (git root to cwd)
  3. `CLAUDE.md`
  4. `.cursorrules`
- **Which cwd:** the CLI uses its launch directory. Gateway sessions use `terminal.cwd`, or `~` when unset ([D] configuration, "Working Directory"; [M] `agent/system_prompt.py:713`). Under the Docker backend the default cwd is the container's home, so the smoke test must show which host path Hermes reads AGENTS.md from.
- **Injection scan:** a project context file that trips the scanner is blocked.
- **`$HERMES_HOME/SOUL.md` is the identity slot.** If present it replaces the default identity text (*verified*, [M] `agent/system_prompt.py:545-550`), so a pointer there must keep the seeded identity.
- **`skills.auto_load: [verdikta-discover]`** puts the whole skill into every session's prompt (about 8 KB). Not recommended as the default.

## Web tools and redirects (the rule-5 question)

- **`web_extract` cannot be relied on to report the final URL** (*verified*). Its result keeps only `{url, title, content, error}` ([M] `tools/web_tools_truncate.py:184`).
  - On the default keyless backends (Exa and Firecrawl free tiers, `web.keyless_fallback`), `url` is the URL that was asked for ([M] `plugins/web/keyless_mcp.py` `exa_extract_keyless`, `firecrawl_extract_keyless`: `_page(url, …)`). A redirect is invisible.
  - Keyed backends report the vendor's URL. Firecrawl's `sourceURL` is documented inconsistently ([M] `web_tools_extract.py:183`).
  - The fetch happens at a third-party vendor, so Hermes has no redirect limit.
- **`web_search`** fetches nothing; it returns result URLs.
- **The built-in `browser_navigate` reports the final URL** and blocks a redirect to a private address (*verified*, [M] `tools/browser_tool.py:742-784`, `response = {"success": True, "url": final_url, "title": title}` plus a compact snapshot).
  - It exists only with `browser.backend: off`.
  - With `browser.backend` unset, the model gets `browser_exec` instead (Python; shows a URL only if the code prints one) ([M] `tools/browser_use_cli.py:236-242`).
  - Under the Docker backend the browser runs inside the sandbox by default (`bot_desktop.placement: auto`; [M] `tools/bot_desktop/placement.py`). The sandbox therefore needs network for browsing.
- **The terminal** can fetch with curl. Plain curl needs no approval, and the web tools' SSRF and blocklist checks do not apply to it.
- **Consequence for rule 5:** on Hermes the tool that "reports where the page came from" is `browser_navigate`, read with `browser_snapshot` if needed. `web_extract` must be named as a tool that hides the final URL.

## Skills hub, submission and scan

- **Hub:** https://hermes-agent.nousresearch.com/docs/skills. Its index (`/docs/api/skills-index.json`) is rebuilt daily and ingests ClawHub automatically.
  - On 2026-10-05 08:03Z it listed `verdikta-bounties-onboarding` but not yet `verdikta-discover`, which was published 2026-10-06.
- **Install from ClawHub:** `hermes skills install clawhub/@nigelon11/verdikta-discover`.
  - ZIP members over 500,000 B are silently dropped. `preview.bundle.mjs` is 376,189 B.
- **Publishing:** there is no Hermes registry form.
  - `hermes skills publish <path> --to github --repo owner/repo` forks the repo and opens a PR, and refuses a "dangerous" verdict.
  - `--to clawhub` is "not yet supported".
  - Official status means a PR into the repo's `optional-skills/`.
  - Other routes: GitHub taps, well-known endpoints, or a direct `owner/repo/path` install.
- **Install-time scan** ("skills guard", [M] `tools/skills_guard.py`):
  - Community sources, ClawHub included: `safe` installs; `caution` (any high) and `dangerous` (any critical) are blocked. `--force` overrides `caution` only.
  - Scanned extensions include `.md .json .txt .js .py .sh`, but **not `.mjs`**.
  - Predicted for 1.0.0: `agent_config_ref` (low, `references/install.md:19`) and `oversized_file` (medium, the bundle), so the verdict is `safe`. This is a prediction from the source, not a run.
  - Pitfalls: renaming the scripts to `.js` would add two high findings. An imperative such as "add … to AGENTS.md" in any scanned file is critical.
- **agentskills.io:**
  - `name`: 1-64 characters, `[a-z0-9-]`, equal to the directory name. `description`: 1-1024 characters.
  - Allowed top-level keys: `license`, `compatibility`, `metadata`, `allowed-tools`.
  - `skills-ref validate` rejects any other top-level key. Nested `metadata.*` passes.
